# Ala-Too Fire Calendar

**Один непрерывный ряд хотспотов с 2000 года для Кыргызстана и пояса соседей.**
MODIS (1 км, с 2000) и VIIRS (375 м, с 2012) приводятся к одной шкале: ложный скачок 2012 года убран калибровкой на годах перекрытия, а не «подкруткой на глаз».

Хакатон-проект. Веб-приложение: рисуешь AOI на карте → получаешь календарь активности год × месяц, аномалию текущего месяца, топ-периоды, график «до/после гармонизации» и CSV.

**Сейчас в репозитории:** рабочий продукт на моках — FastAPI (`/backend`), фронтенд на React + Leaflet + Plotly (`/frontend`), контракт (`/contracts`), страница ограничений и питч-материалы. Pipeline (P2/P3) ещё не влит: пока нет `cells_monthly.parquet`, API честно отвечает `meta.source = "mock"` и отдаёт фикстуры, а фронт умеет работать вообще без бэкенда.

## 1. Зафиксированные решения

| Вопрос | Решение | Почему |
|---|---|---|
| Регион | `bbox = 68.5, 38.4, 80.7, 43.7` (W,S,E,N) — Кыргызстан целиком + пояс соседей (UZ, KZ, TJ, кусок СУАР) ≈ 600 тыс. км² | Влезает в память, объяснимо (весенние палы, летние горные пожары), AOI всё равно произвольный — регион нужен только для калибровки |
| Сетка агрегатов | `0.25°` → 22 × 49 = **1078 ячеек** | API суммирует ячейки за миллисекунды |
| Сетка дедупликации | `0.01°` (~1.1 км), сенсор-независимая | Убирает эффект «375 м даёт больше точек» ещё до регрессии |
| Калибровочные тайлы | `2° × 2°` → 21 тайл | Калибровка не зависит от того, что нарисовал пользователь |
| Единица измерения | `hotspot_days_1km` = Σ по дням (уникальные 1-км ячейки с детекцией) | Одна единица во всём продукте: календарь, аномалия, CSV, график |
| Стек API | FastAPI | Контракт = JSON Schema, OpenAPI бесплатно |
| Стек фронта | **React + Leaflet + Plotly** | Полный контроль над картой и рисованием AOI |
| Фолбэк фронта | Streamlit, **только если к 8-му часу календарь не рендерится** | 3 часа на аварийную переделку, не раньше |
| Палитры | viridis (по умолчанию) + cividis | Обе последовательные и дальтоник-безопасные |

Ключевое число для питча: **перекрытие MODIS × VIIRS = 2012–2026** — это и материал для калибровки, и честная валидация (hold-out 2 года).

## 3. Структура и запуск

```
/data            # сырьё FIRMS (в .gitignore; как скачать — data/README.md)
/pipeline        # ingest → grid → aggregate → harmonize → validate (P2/P3, ещё не влит)
/backend         # FastAPI: /aoi/summary, /calendar, /anomaly, /top, /export.csv, /harmonization
/frontend        # React + Leaflet + Plotly, сборка Vite
/contracts       # JSON Schema = контракт стыков + фикстуры
/docs            # архитектура, роли, метод, ограничения, питч
README.md
```

**Принцип:** тяжёлое считается заранее. Pipeline превращает сырые точки в месячные агрегаты по 0.25° ячейкам (Parquet); API на запрос AOI только суммирует ячейки; сырые точки нужны только для CSV. Поэтому фронт с первого часа работает на `contracts/fixtures/`, не дожидаясь данных.

### Запуск

```bash
# 1. API, из корня репозитория
python -m venv .venv
.venv/Scripts/pip install -r backend/requirements-dev.txt     # Windows
# .venv/bin/pip install -r backend/requirements-dev.txt       # Linux / macOS
.venv/Scripts/python -m uvicorn app.main:app --app-dir backend --port 8000

# 2. Фронтенд, второй терминал
cd frontend
npm ci
cp .env.example .env        # выставить VITE_USE_MOCK=false, чтобы шли запросы к API
npm run dev                 # http://localhost:5173, /api проксируется на :8000
```

С `VITE_USE_MOCK=true` (по умолчанию) фронт живёт на `contracts/fixtures/` и бэкенд не нужен — режим для верстки и демо без сети. С `false` все пять блоков берут данные из API; `meta.source` в шапке показывает, откуда они на самом деле.

> `npm` не работает по UNC-пути `\\wsl$\...`: фронтенд запускать внутри WSL или на нативной файловой системе.

### Проверки

```bash
.venv/Scripts/python -m pytest        # 38 тестов, включая валидацию ответов по JSON Schema
.venv/Scripts/python -m ruff check .
cd frontend && npm run build && npm test   # сборка Vite + 9 unit-тестов
```

## 4. Метод гармонизации (один, без вариантов)

1. **Выравнивание разрешения.** Сырые детекции снапятся в решётку `0.01°`, считаются уникальные `(ячейка, дата)`. Кластеры 375-метровых пикселей VIIRS схлопываются в ту же 1-км ячейку, что и пиксель MODIS.
2. **Калибровка на перекрытии.** По тайлам `2°` и сезону, на месячных счётчиках: `log1p(MODIS) = a + b · log1p(VIIRS)`, робастная регрессия, усадка к глобальной подгонке при малом `n`.
3. **Единый ряд.** `< 2012` — MODIS как есть. `≥ 2012` — VIIRS в MODIS-эквиваленте, с интервалом неопределённости из ошибок коэффициентов.
4. **Валидация.** Два года перекрытия исключены из подгонки и служат hold-out: RMSE в логарифмах, MAPE, смещение. Отдельный **тест скачка**: `step_ratio` в точке 2012 до и после + плацебо-год, чтобы доказать, что мы не сгладили всё подряд.

Точные числа (step_ratio до/после, holdout MAPE, RMSE) появятся в `docs/method.md` после прогона pipeline — сейчас в репозитории формулы, а не выдуманные проценты. Единственные числа, которые уже зафиксированы, — в `contracts/fixtures/` и помечены `meta.source = "mock"`.

## 5. Ограничения

- Облака, дым и пыльные бури дают ложные детекции; дым маскирует соседние очаги.
- Хотспот ≠ пожар: детекция — это 1 км² «чего-то горячего», а не подтверждённое возгорание.
- Гармонизация — **оценка**, не измерение; у неё есть интервал, и он рисуется на графике.
- Текущий месяц неполный: сравнение идёт «месяц-к-дате», иначе аномалия систематически занижена. За это отвечает поле `days_observed`.
- NRT-данные догоняют с задержкой; последние месяцы помечены `nrt`.
- Данные: NASA FIRMS, MODIS/VIIRS active fire (2000–2026). Атрибуция обязательна.
