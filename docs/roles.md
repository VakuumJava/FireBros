# Роли: 5 разработчиков, модульная разработка

## Принцип

Делим **не по слоям мышления, а по директориям**. У каждой директории ровно один владелец. Это единственное правило, которое защищает от «все правят всё» на пяти людях за сутки.

| Директория | Владелец | Кто может писать | Кто только ревьюит |
|---|---|---|---|
| `contracts/` | P1 | P1 | все |
| `pipeline/firebros/ingest.py`, `grid.py`, `aggregate.py`, `build.py` | P2 | P2 | P1, P3 |
| `pipeline/firebros/harmonize.py`, `validate.py` | P3 | P3 | P1, P2 |
| `backend/` | P1 | P1 | P2 (CSV-путь), P4 (форма ответа) |
| `frontend/src/components/`, `src/api/` | P4 | P4 | P1, P5 |
| `frontend/src/ui/`, `docs/limitations.md`, `docs/pitch/` | P5 | P5 | P1, P4 |
| `README.md`, `.github/` | P1 | P1 | все |

Правило одно: **PR в чужую директорию мержится только с approve владельца.** Не «нельзя», а «через ревью» — иначе на стыке двух людей всё разъедется за час.

## P1 · Интеграция, контракт API, ревью — ты

**Зона:** `contracts/`, `backend/`, `.github/`, `README.md`.

**Делает:**
- В первый час: фиксирует регион, bbox, сетки, схемы пяти ответов и фикстуры. Это первый коммит, на нём начинают все остальные.
- Держит `GET /api/v1/aoi/{summary,calendar,anomaly,top,harmonization}` + `/export.csv`; `store.py` с двумя реализациями (`mock` → `parquet`), чтобы роутеры не переписывались, когда придут данные.
- CI: линт, тесты, **drift-check** — фикстуры обязаны валидироваться против схем, иначе сборка красная.
- Ревью всех PR, разрешение конфликтов на стыках, деплой, финальный текст сабмишна вместе с P5.

**Вход:** Parquet от P2, `calibration.parquet` от P3, компоненты от P4.
**Выход:** JSON строго по `/contracts`.

**DoD:** `curl` каждого из пяти эндпоинтов валидируется схемой; при отсутствии parquet API поднимается на моках и честно пишет `meta.source = "mock"`; один и тот же запрос даёт одинаковую форму ответа в обоих режимах.

**Не трогает:** `pipeline/*` (только ревью), внутренности компонентов P4.

**Первые 60 минут:** bbox и сетки → схемы + фикстуры → коммит «contract freeze» → раздать ссылки.

## P2 · Данные: загрузка, дедуп, сетка, агрегаты, CSV-стор

**Зона:** `pipeline/firebros/{ingest,grid,aggregate,build}.py`, `data/README.md`.

**Делает:**
- `ingest.py`: FIRMS area API, окна по 5 дней, ретраи, дедуп по `(sensor, lat, lon, acq_date, acq_time)`, разложение в `data/raw/<sensor>/<year>/`.
- `grid.py`: снап в решётку `0.01°`, уникальные `(ячейка, дата)`. Здесь рождается единица `hotspot_days_1km` — и больше нигде не переопределяется.
- `aggregate.py`: месячные суммы по `0.25°` + `days_observed` + партиции `hotspots/*.parquet` для CSV.
- `build.py`: один прогон 2000→2026 одной командой, `manifest.json` с датой сборки, диапазоном и хэшами входов.

**Вход:** `data/raw/**` + `FIRMS_MAP_KEY`.
**Выход:** `cells_monthly.parquet`, `hotspots/*.parquet`, `manifest.json`.

**DoD:** повторный прогон даёт побайтово тот же `cells_monthly.parquet` (идемпотентность); ни одного дубля `(cell, date, sensor)`; `days_observed` совпадает с числом дней в исходниках; время полной сборки < 30 мин.

**Не трогает:** `harmonize.py`, `validate.py` (P3), `backend/` (P1).

**Первые 60 минут:** ключ, bbox, скачать 2019–2026 (свежие годы быстрее) → первый Parquet → отдать P1 для проверки формы.

## P3 · Наука: гармонизация, калибровка, неопределённость, валидация

**Зона:** `pipeline/firebros/{harmonize,validate}.py`, `docs/method.md`.

**Делает:**
- `harmonize.py`: по тайлам `2°` и сезону робастная регрессия `log1p(MODIS) = a + b·log1p(VIIRS)` на перекрытии 2012–2025; усадка к глобальной подгонке при малом `n`; интервал неопределённости из ошибок коэффициентов.
- `validate.py`: hold-out 2024–2025 (исключены из подгонки), метрики в логарифмах и в счётчиках, **тест скачка**: `step_ratio` в точке 2012 до и после + плацебо-год, чтобы доказать, что мы не «сгладили всё подряд».
- Одна-единственная функция аномалии (медиана, MAD, month-to-date) — её импортирует и API, и отчёт.

**Вход:** `cells_monthly.parquet` (месячные счётчики по 0.25° и по тайлам).
**Выход:** `calibration.parquet`, `harmonization_report.json`, `docs/method.md` с числами.

**DoD:** `step_ratio_harmonized ∈ [0.95, 1.05]` при `step_ratio_raw ≥ 1.5`; `step_ratio_placebo` в тех же пределах; holdout MAPE и RMSE зафиксированы в `docs/method.md`; ни одного числа в питче, которого нет в отчёте.

**Не трогает:** `ingest.py`, `aggregate.py`, `backend/`, `frontend/`.

**Первые 60 минут:** получить от P2 хотя бы 2012–2026, посчитать `step_ratio` «до» — это уже главный слайд.

## P4 · Фронтенд: карта, календарь, графики, CSV

**Зона:** `frontend/src/components/`, `frontend/src/api/client.js`.

**Делает:**
- Карта (Leaflet + Leaflet.draw) → bbox или полигон → в URL запроса. Плюс ручной ввод lat/lon как обязательный дубль.
- Календарь год × месяц: viridis/cividis, переключатель, `null` рисуется отдельным паттерном, легенда из `max` ответа.
- Аномалия: медиана, σ, процентиль, цветовой индикатор, подпись из `label`.
- График «до/после 2012»: две линии + полоса неопределённости; `step_ratio` выводится числом рядом.
- Кнопка CSV: `kind=hotspots` и `kind=monthly`, имя файла из `Content-Disposition`, показ `X-Row-Count`.

**Вход:** `contracts/fixtures/*.json` с часа 0, живой API с часа 2–6.
**Выход:** 5 блоков UI + клиент API.

**DoD:** приложение полностью работает на фикстурах без бэкенда; `null` нигде не превращается в `0`; календарь рендерится < 300 мс на 27 годах; клавиатурная навигация по календарю; ни одного пересчёта шкалы на клиенте.

**Не трогает:** `backend/`, `pipeline/`, тексты ограничений (P5).

**Первые 60 минут:** скелет Vite + Leaflet, карта региона, календарь на фикстуре. Никакого API пока нет — и не нужен.

## P5 · Дизайн, доступность, ограничения, питч

**Зона:** `frontend/src/ui/`, `docs/limitations.md`, `docs/pitch/`.

**Делает:**
- Страница «Ограничения»: облака и дым, хотспот ≠ пожар, гармонизация — оценка, неполный текущий месяц, NRT-задержка, атрибуция NASA.
- Палитры и доступность: viridis/cividis как единственные последовательные шкалы, проверка контраста подписей, внятные единицы («хотспот-дни, 1 км»), подписи осей.
- Питч: 6 слайдов, сценарий демо на 90 секунд с таймингом, запись видео, текст сабмишна.

**Вход:** работающий UI от P4, числа из `docs/method.md` от P3.
**Выход:** тексты, страница ограничений, слайды, видео.

**DoD:** демо укладывается в 90 секунд по прогону с секундомером; каждая цифра на слайде имеет источник в `docs/method.md`; страница ограничений читается за 40 секунд и не выглядит как дисклеймер.

**Не трогает:** логику компонентов P4 (только стили и тексты), `pipeline/`, `backend/`.

**Первые 60 минут:** черновик страницы ограничений и структура слайдов — они не зависят ни от данных, ни от кода.

## Стыки: кто кому что отдаёт и когда

| # | Что | От | Кому | Когда | Приёмка |
|---|---|---|---|---|---|
| 1 | bbox, сетки, схемы, фикстуры | P1 | P2, P3, P4 | час 0–1 | P4 начал верстать на фикстурах |
| 2 | первый `cells_monthly.parquet` (2–3 года) | P2 | P3 | час 2–3 | P3 посчитал `step_ratio` «до» |
| 3 | полный Parquet 2000–2026 | P2 | P1 | час 4–6 | API отдаёт реальные числа |
| 4 | `calibration.parquet` + метрики | P3 | P1, P5 | час 6–9 | график «до/после» на реальных данных |
| 5 | UI на реальном API | P4 | P5 | час 8–10 | демо целиком проходится |

**Правило стыка:** каждый артефакт передаётся вместе с командой, которой его можно воспроизвести. «У меня работает» — не приёмка.

## Протокол мержа

- Ветки: `feat/p2-ingest`, `feat/p3-calibrate`, `feat/p4-calendar`, `feat/p5-limits`. `main` всегда рабочий.
- Маленькие PR (≤ 400 строк), мерж после зелёного CI и approve владельца директории.
- Изменение контракта — отдельный PR с меткой `contract`, только P1, только до «заморозки» на часе 1; дальше — аддитивные поля.
- Конфликты на стыке решает P1, не автор PR.
- Коммит-сообщения: `p2: ingest 5-day windows`, `p3: tile calibration fit`, `p4: calendar heatmap`.

## Если кто-то отстаёт (решения заранее, чтобы не спорить в час ночи)

| Отстаёт | Что делаем | Что честно пишем в UI/питче |
|---|---|---|
| P3 (калибровка) | v0: одна глобальная пара `(a, b)` на всю область вместо тайлов, интервал ±15 % | «калибровка глобальная, тайловая — в следующей итерации» |
| P2 (полный диапазон) | грузим 2000–2014 + 2019–2026, пробел помечаем `null` | «пробел в данных, а не ноль» |
| P4 (`Leaflet.draw`) | остаются поля ввода bbox lat/lon — это обязательный минимум по заданию | «рисование AOI — следующий шаг» |
| P4 (график до/после) | статичный PNG из ноутбука P3 + числа рядом | график всё равно показывает главный аргумент |

Ни один фолбэк не ломает единицу измерения и контракт. Ломается только красота — это приемлемая цена.
