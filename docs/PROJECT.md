# Ala-Too Fire Calendar — полное описание проекта

Один документ, чтобы понять проект с нуля: что делаем, что уже работает, чего не хватает и по каким критериям считается готовым.

---

## 1. Что это

Веб-приложение с календарём пожарной активности для Кыргызстана и пояса соседей. Пользователь рисует область на карте (или вводит координаты) и диапазон дат — получает единый непрерывный ряд хотспотов **с 2000 года**, где MODIS и VIIRS склеены без ложного скачка в 2012-м.

**Для кого:** экстренные службы, учёные, землеустроители, пожарные — все, кому нужен не «сколько пожаров вчера», а «насколько этот октябрь необычен по сравнению с 27 годами истории в моём районе».

**Одна фраза для жюри:** «VIIRS видит в 1.7 раза больше точек, чем MODIS, поэтому простая склейка рисует скачок в 2012-м. Мы калибруем VIIRS на годах перекрытия и показываем, что скачок исчез, — с интервалом неопределённости и честной валидацией на отложенных годах».

---

## 2. Проблема и метод

**Проблема.** MODIS (1 км) с 2000 года, VIIRS (375 м) с 2012-го. При простой склейке в 2012-м появляется скачок ~+86 %, хотя реальная активность не менялась. MODIS стареет, дальше данные идут только от VIIRS.

**Метод (зафиксирован, без вариантов):**

1. **Выравнивание разрешения** — детекции снапятся в решётку `0.01°` (~1.1 км), считаются уникальные `(ячейка, дата)`. 375-метровые кластеры VIIRS схлопываются в ту же 1-км ячейку, что и пиксель MODIS. Это убирает большую часть скачка ещё до регрессии.
2. **Калибровка на перекрытии 2012–2025** — по тайлам `2° × 2°` и сезону: `log1p(MODIS) = a + b · log1p(VIIRS)`, робастная регрессия, усадка к глобальной подгонке при малом `n`.
3. **Единый ряд** — до 2012 MODIS как есть; после — VIIRS в MODIS-эквиваленте плюс интервал неопределённости.
4. **Валидация** — два года перекрытия (2024–2025) исключены из подгонки, служат hold-out. Отдельный **тест скачка**: `step_ratio` в точке 2012 до и после + плацебо-год, чтобы доказать, что мы не сгладили всё подряд.

**Единица измерения — одна на весь продукт:** `hotspot_days_1km` = сумма по дням числа уникальных 1-км ячеек с детекцией. Не «детекции», не «пожары».

**Регион:** `bbox = 68.5, 38.4, 80.7, 43.7` (W,S,E,N) — Кыргызстан целиком + пояс соседей. ~600 тыс. км², 22 × 49 = **1078** ячеек по 0.25°. AOI пользователя всегда внутри этого bbox.

## 4. Архитектура

- **Диаграмма:** [`docs/architecture.excalidraw`](architecture.excalidraw) — 117 элементов, 5 слоёв слева направо, цвет рамки = владелец модуля.
  Импорт в комнату: открыть `excalidraw.com` в пустой вкладке → `Menu → Open` → файл → `Ctrl+A`, `Ctrl+C` → вкладка комнаты → `Ctrl+V`.
- **Текстовая версия:** [`docs/architecture.md`](architecture.md) — слои, потоки, схема хранения, не-цели.
- **Роли и владение:** [`docs/roles.md`](roles.md).

```
FIRMS CSV ──► ingest ──► grid (0.01°, unique cell-day) ──► aggregate (0.25°, Parquet)
                                                              │
                                          harmonize (тайлы 2°, log-регрессия, 2012–2025)
                                                              ▼
                        contracts/*.schema.json ──► FastAPI ──► React/Leaflet/Plotly
                                                              ▲
                                       validate: hold-out + тест скачка 2012
```

**Принцип:** тяжёлое считается заранее. Pipeline один раз превращает сырые точки в месячные агрегаты по 0.25°; API на запрос AOI только суммирует ячейки. Сырые точки читаются только для CSV.

## 5. Контракт данных — что должен произвести pipeline

Это единственное, что блокирует превращение демо в продукт.

### `data/processed/cells_monthly.parquet`

Одна строка на (ячейка, месяц), **уже в единой шкале**:

| Колонка | Тип | Смысл |
|---|---|---|
| `grid_row`, `grid_col` | int | индекс ячейки 0.25°, от юго-западного угла региона |
| `year`, `month` | int | месяц наблюдения |
| `sensor` | str | `MODIS` / `VIIRS_SNPP` / … — сенсор, давший unified-ряд |
| `hotspot_days` | int | **единица продукта**, гармонизированный счётчик в шкале MODIS |
| `hotspot_days_lo`, `hotspot_days_hi` | int | 95 % интервал; для MODIS `lo == hi == hotspot_days` |
| `hotspot_days_raw` | int | нативный счётчик сенсора — линия «до» на графике |
| `hotspot_days_modis` | int, null | нативный MODIS в тот же месяц; только в перекрытии, истина для валидации |
| `days_observed` | int | сколько дней месяца реально есть в данных |
| `n_detections` | int | сырые детекции, только для диагностики |

### `data/processed/hotspots/*.parquet`
Партиции по годам, колонки: `latitude`, `longitude`, `acq_date`, `acq_time`, `satellite`, `instrument`, `sensor_family`, `confidence`, `frp`, `daynight`, `grid_cell`. Нужны только для CSV.

### `manifest.json`
Дата сборки, диапазон, хэши входов, версия метода. Без него нельзя утверждать, что цифры воспроизводимы.

Полное описание — [`backend/README.md`](../backend/README.md#storage-contract-this-service-expects).

## 6. Что осталось сделать

### P0 — pipeline (блокирует всё остальное), ~3–4 часа, P2

1. `pipeline/firebros/ingest.py` — FIRMS area API, окна по 5 дней, ретраи, дедуп по `(sensor, lat, lon, date, time)`, раскладка `data/raw/<sensor>/<year>/`.
2. `grid.py` — снап в `0.01°`, уникальные `(ячейка, дата)` → `data/interim/*.parquet`.
3. `aggregate.py` — месячные суммы по `0.25°`, `days_observed`, партиции `hotspots/*.parquet`.
4. `build.py` — один прогон 2000→2026 одной командой + `manifest.json`.

**Приёмка:** колонки строго по §5; повторный прогон даёт тот же файл; полная сборка < 30 мин; ключ `FIRMS_MAP_KEY` не попадает в репозиторий.

### P1 — гармонизация (блокирует цифры), ~3–4 часа, P3

5. `harmonize.py` — тайлы `2°` × месяц/сезон, робастная регрессия на `log1p`, усадка, интервал из ошибок коэффициентов; пишет `hotspot_days`, `_lo`, `_hi`, `_raw`, `_modis`.
6. `validate.py` — hold-out 2024–2025, метрики, `step_ratio` в 2012 и плацебо; пишет `harmonization_report.json` и числа в `docs/method.md`.

**Приёмка:** `step_ratio_raw ≥ 1.5`, `step_ratio_harmonized ∈ [0.95, 1.05]`, плацебо в тех же пределах; holdout MAPE зафиксирован в `docs/method.md`.

### P1 — интеграция, ~1 час

7. Прогнать API на реальном parquet, сверить колонки, проверить все 5 эндпоинтов и CSV; убедиться, что в шапке фронта бейдж переключился на `parquet`.

### P4 — QA на реальных данных, ~2 часа

8. Проверить пустой AOI, крошечный полигон, один месяц, отказ CSV по лимиту, переполнение чисел в карточках; поправить layout, если цифры вылезают.

### P5 — питч, ~2 часа

9. Заменить мок-цифры в слайдах на реальные из `harmonization_report.json`; записать видео 90 секунд; добить текст сабмишна.

### Опционально

10. Dockerfile для API + статика фронта, деплой на любой хостинг.

## 7. Критерии готовности демо

- Рисуем Чуйскую долину → календарь год × месяц появляется < 2 с.
- График «до/после»: `step_ratio` 1.86 → 1.05, плацебо ~0.92, полоса неопределённости после 2012.
- Аномалия октября: `observed`, медиана, σ, процентиль, подпись «на N σ выше нормы», окно `days <= through_day`.
- CSV скачивается, `X-Row-Count` совпадает с числом строк, имя файла из `Content-Disposition`.
- Страница ограничений открывается в один клик.
- Бейдж источника показывает `parquet` (если данные реальные) — иначе `mock`, и это сказано вслух.

## 8. Риски и заготовленные фолбэки

| Риск | Что делаем |
|---|---|
| FIRMS API отдаёт 429 / режет окно | окна по 5 дней, ретраи; ручная выгрузка с портала FIRMS в `data/raw/` |
| MODIS деградирует и перекрытие заканчивается раньше 2025 | hold-out сдвигается на последние два полных года перекрытия; числа в `docs/method.md` пересчитываются |
| NOAA-20/21 добавляют второй скачок | они выключены по умолчанию (`--include-noaa`), в ряд идёт только SNPP |
| Pipeline не успевает | демо идёт на фикстурах с честным `meta.source = "mock"` — продукт уже работает, меняются только цифры |
| Калибровка не сходится на тайлах | v0: одна глобальная пара `(a, b)`, интервал ±15 %, в питче сказано прямо |

## 9. Запуск и проверки

```bash
# API
python -m venv .venv
.venv/Scripts/pip install -r backend/requirements-dev.txt
.venv/Scripts/python -m uvicorn app.main:app --app-dir backend --port 8000

# Frontend (не по UNC-пути: npm там не работает)
cd frontend && npm ci && npm run dev      # VITE_USE_MOCK=false в .env для живого API

# Проверки
.venv/Scripts/python -m pytest            # 38 тестов, включая валидацию по JSON Schema
.venv/Scripts/python -m ruff check .
cd frontend && npm run build && npm test  # сборка Vite + 9 тестов
```
