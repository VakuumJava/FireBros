# /contracts — единственный источник правды для стыков

Фронт и бэкенд не договариваются между собой словами. Они договариваются **этими файлами**. Изменил поле — изменил схему, фикстуру и PR одновременно, иначе ревью не проходит.

```
contracts/
  aoi-summary.schema.json        # единый ряд по месяцам + покрытие
  aoi-calendar.schema.json       # матрица год × месяц
  aoi-anomaly.schema.json        # текущий месяц vs история
  aoi-top.schema.json            # топ месяцев и лет
  aoi-harmonization.schema.json  # до/после 2012 + метрики валидации
  fixtures/*.json                # сгенерированные ответы (mock)
```

## Правила, которые нельзя нарушать

1. **Единица измерения одна:** `hotspot_days_1km` = Σ по дням (уникальные 1-км ячейки с детекцией). Не «число детекций», не «число пожаров». Поле `meta.unit` присутствует везде.
2. **`null` ≠ `0`.** В календаре `null` = нет данных (пробел), `0` = данных нет, но месяц наблюдался. Фронт не имеет права рисовать `null` нулём.
3. **`days_observed` обязателен.** Текущий месяц неполный; NRT догоняет. Любая агрегация без этого поля — враньё.
4. **Интервал только после 2012.** До 2012 `lo == hi == count`: MODIS — опорная шкала, а не оценка.
5. **`meta.source`** явно говорит `parquet` или `mock`. Мок никогда не выдаётся за измерение — ни в UI, ни на проекторе.
6. **Никаких пересчётов шкалы на фронте.** Легенда календаря использует `max` из ответа, а не максимум по видимым данным.

## Фикстуры

`fixtures/*.json` — замороженные ответы, снятые с мока на часе 0. Они уже валидны против схем и содержат всё, что нужно фронтенду, чтобы не ждать бэкенд:

- `aoi-summary.json`, `aoi-calendar.json`, `aoi-anomaly.json`, `aoi-top.json`, `aoi-harmonization.json`.

Когда появится `backend/`, рядом ляжет генератор (`tools/dump_fixtures.py`), и фикстуры будут пересобираться из того же кода, что отдаёт API. До этого они правятся руками — но **только вместе со схемой** в одном PR.

Фикстуры **специально** содержат:
- ложный скачок в `raw` на 2012 (+86% по step-ratio) и его отсутствие в `harmonized` (~1.05);
- неполный 2026-11 с `days_observed: 14`;
- `null` в последнем месяце календаря.

## Протокол «заморозки» (первый час)

1. P1 создаёт схемы и фикстуры — это первый коммит.
2. P2/P3/P4 начинают на фикстурах **до** появления реальных данных.
3. Любое изменение контракта — PR с меткой `contract`, ревью P1, и только потом код.
4. Схема считается замороженной после часа 1. После этого меняются только **аддитивные** поля (`x-foo`, новые необязательные ключи), не ломающие клиентов.

## Что ещё живёт здесь

`GET /api/v1/aoi/export.csv?kind=hotspots|monthly` возвращает `text/csv`, не JSON, поэтому схемы у него нет — колонки описаны в [`docs/api-contract.md`](../docs/api-contract.md).
